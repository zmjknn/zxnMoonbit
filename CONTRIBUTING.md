# Contributing to MoonMark

## Before opening a PR

Run the same checks used by the project CI:

```bash
moon fmt --check
moon check --deny-warn
moon test
moon bench
moon run src/cli -- --help
git diff --check
```

For a directory-conversion change, also run a temporary nested-directory smoke test and verify that relative output paths are preserved. Do not commit generated build directories or dependency caches.

## Change and test expectations

- Parser, span, renderer, and URL-policy changes must include focused regression tests.
- Keep performance claims tied to a named workload and a recorded `moon bench` run; do not present one machine's result as a universal guarantee.
- Update both `README.md` and `README_zh.md` when user-visible behavior or validation commands change.
- `pkg.generated.mbti` files are generated by `moon info`; do not hand-edit them. Review generated interface changes before committing.

## Licensing and references

MoonMark is distributed under Apache-2.0. Keep the copyright and license header on hand-authored source files. `REFERENCES.md` records the MIT-licensed projects used as design references; do not copy code or omit required notices from a third-party project.

## Commit and PR description

Describe the scope of the change, boundary cases covered, verification commands, and any benchmark workload/results. Never commit passwords, access tokens, local credential files, `_build`, or `.mooncakes` contents.
